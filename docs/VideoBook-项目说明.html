01 · 项目定位

项目背景与作品概述

视频已成为技术学习、软件演示和课程传播的重要载体，但其内容天然沿时间轴排布。读者查找一个结论、复现一个操作或回看一张板书，往往必须反复拖动进度条。平台字幕能提供文字，却通常保留口语、错词和碎片化顺序；直接导出字幕并不能形成可用的教材。

VideoBook 是一个面向 YouTube 与 Bilibili 的本地工具箱与 AI 助手工作流。用户提交视频链接后，系统取得平台字幕；无字幕时可用本地语音识别生成带时间戳的文本。AI 助手依据字幕、视频章节及可选的课程官方资料重构知识结构，写出 Markdown；随后脚本把关键时间点的画面、官方幻灯片和视频回链嵌入书稿，并生成可在浏览器阅读的 HTML。

相关课堂研究发现，在其受试条件下，为课程视频附上自动摘要有助于学习者完成材料测验[1]；这为“视频加可读文本”的形态提供参考，但不直接证明本项目的学习效果。

交付对象：book.md 适合编辑、版本管理与二次加工；book.html 适合阅读和演示。二者与图片放在 output/<视频ID>/ 下。

作品边界

  • 现有稳定流程由多个脚本和 AI 助手协同完成；src/agent.py 目前只是字幕阶段向导，不能把它表述成独立的一键全自动产品。
  • 电子书是对原视频的学习辅助。截图、字幕和课件仍受原作者及平台权利约束，项目代码的开源许可不能替代内容授权。
  • 公式视觉识别正在样例片段中验证，独立实验不能代表全视频、全学科的自动准确率。

本报告阅读路径

02 · 问题分析

当前痛点：视频内容难以沉淀

定位慢

长视频按时长组织，概念、示例和操作步骤分散。读者知道“讲过”，却难以迅速找到所在位置。

字幕不等于教材

自动字幕常有同音词、英文术语和断句错误；逐字稿缺乏层级、前后依赖、图示和可执行步骤。

画面信息会丢失

代码、界面、板书、公式端点与幻灯片布局无法只靠口述恢复。纯文字总结容易省略关键证据。

复核成本高

读者需要在总结与原视频之间反复切换。没有时间锚点，错误难以发现，也不便于向他人解释出处。

难以复核

传统做法把“转写”当成终点；VideoBook 需要解决的是从时间序列到知识结构的转换，并把关键视觉证据和原视频位置保留下来。AI 擅长语言重组，但必须受来源约束；否则流畅文本会掩盖漏写和误读。

高数样例暴露的具体问题

在本地一段 20:00–35:00 的高数视频试验中，人工核对出 9 组公式或关键例子，其中 6 组的具体内容未进入原书。区间端点、定义域括号等信息在 ASR 中不完整，须回看画面和附近口述。这说明“只按现成书稿选图”会漏掉未被书稿提及的关键视觉知识。

以上 9 组是样例检查中发现的候选，不代表该片段公式总数，也不能据此推导全片召回率。

长视频章节生成研究也采用带时间戳的语音转写与画面描述来确定主题边界[3]；VideoBook 借鉴这种多源信息思路，但仍由 AI 助手和人工审校形成最终章节。

关键数据原则：时间戳贯穿字幕、截图、视频卡片和人工核对；保留原始字幕与独立书稿，便于在发现错词或漏图后追溯。

架构 / 数据流05 / 14
05 · AI 核心作用

AI 决定“读得懂”，证据决定“信得过”

1. 语音转文字：为无字幕视频建立时间轴

当平台没有可用字幕时，本地 faster-whisper 对音轨执行 ASR，并输出与平台字幕同构的 transcript.json。这一步让原本不可搜索的讲解进入后续书籍化流程。其基础 Whisper 模型见相关研究[2]；领域术语提示可缓解专有名词错听，但转写仍需校订。

2. 语义重构：把口语过程写成知识结构

大语言模型读取转写文本、视频章节和可用的官方讲义，归纳主题、理顺前后依赖、统一术语，将冗长口语重写为章节、步骤、表格、代码块和要点。对于非中文原视频，工作流要求翻译为中文。它还要为需要视觉证据的位置标注时间戳，使后续脚本能准确配图。

3. 跨模态校准：文字与画面相互制约

截图、幻灯片、板书和附近字幕共同帮助核对模型文本。官方讲义可校准术语与章节，幻灯片可补足视频帧的清晰度；画面可发现字幕未记录的界面与数学符号。带时间边界的视频描述[4]和“关键帧—说明文字”配对摘要[5]是相关研究方向；本项目采用原始画面、官方资料和视频回链约束 AI 概括。

4. 视觉公式识别：验证中的扩展

当前工作区有独立实验：对 15 分钟视频片段取时间序列画面，视觉模型提出候选，再看高清单帧与邻近字幕，生成可核对的公式书稿。首读曾将 [-1,2) 误写成 [-1,2]，审校后才纠正。它显示 AI 可以帮助发现遗漏，也说明端点等细节必须经过画面复核；该功能尚不能被表述为通用的一键准确识别。

核心原则：模型负责提取、组织和提出候选；事实性公式、步骤和结论以画面、字幕、官方资料及人工复核为准。

AI 价值 / 边界06 / 14
06 · 功能清单 A

作品功能：从视频到初稿

视频识别与字幕提取

支持 YouTube、Bilibili 视频链接；解析视频 ID、标题、时长与可用章节。平台字幕被整理为带开始/结束时间的分段 JSON。脚本提供字幕覆盖率提示，低覆盖率意味着不应直接进入书稿改写。

本地 ASR 兜底

平台确无字幕时，只获取音轨，由 faster-whisper 转写。支持抽样试跑、领域术语提示、GPU/CPU 配置和进度续跑。样例中 ASR 为数学视频生成了全段转写，但错词仍需人工或 AI 对照校正。

AI 书稿编排

助手按主题而非机械按原视频章节组织内容：给概念取标题，提炼解释顺序，把操作写成步骤，并为关键画面插入 SCREENSHOT:HH:MM:SS 标记。书稿要求保留原视频真实主张，不能凭常识补出讲者没有展示的论据。

字幕对照与校订

make_corrected.py 可生成逐段字幕对照稿，保留时间与原话顺序，修明显错词和口癖；重跑默认保护既有人工修订。此稿便于核对 AI 书稿和原讲解，发布时可作为可选附件。

典型结果：一个样例技术视频生成了 10 个主题章节、17 张播放器截图和可阅读 HTML；数字仅代表该次本地样例，不是产品对任意视频的固定产量。

功能 / 内容生成07 / 14
07 · 功能清单 B

作品功能：配图、阅读与发布

播放器截帧

capture_frames.py 读取书稿中的时间标记，通过专用 Chrome 配置访问已登录播放器，截取清晰的视频帧并替换图片占位。首次需在专用浏览器窗口登录；之后可复用登录态。脚本优先补拍缺失帧，失败时可用视频源与 ffmpeg 抽帧兜底。

官方资料增强

有课程主页时，course_assets.py 抓取讲义、提取幻灯片文字，并可把课件渲染为高清图片。感知哈希提供视频帧与官方幻灯片的匹配候选；确认后可用更清楚的官方图替换糊帧。审计命令检查每页幻灯片是否在书中恰好出现一次。

HTML 阅读体验

post_process.py 将 Markdown 转为暗色主题 HTML，支持图片点击放大、表格、代码块、目录和视频卡片。静态图卡提供时间回链；缺少本地图时可显示平台嵌入播放器。B 站分 P 参数会保留在回链中，避免跳错集数。

本地预览与可选公开发布

本地 HTTP 服务用于浏览书稿并确保视频嵌入正常。publish.py 可将成品文件整理到独立 pages 分支；完成 GitHub Pages 设置和推送后，读者可通过网页访问。公开发布前要确认视频画面、字幕、课件的授权与署名。

开发栈 / 约束09 / 14
09 · 使用说明

普通用户：从链接到电子书

  1. 准备环境。克隆仓库，安装 requirements.txt；在工作目录中启动能读取本项目文件的 AI 助手。浏览器截帧需要 Chrome，首次使用 B 站登录内容时在专用配置中登录一次。
  2. 给出链接和期望。例如：“请把这条 B 站课程做成 VideoBook，保留重要演示画面和原视频时间，先核对字幕错词，再输出 Markdown 与 HTML。”如有官方课程主页，一并提供。
  3. 检查助手的阶段结果。确认字幕是否覆盖主要内容；无字幕时确认 ASR 抽样质量。查看书稿目录是否符合讲解逻辑，检查关键操作、板书和演示是否有时间标记。
  4. 审阅视觉证据。抽查有代表性的图片、关键术语、时间回链和可能的公式。画面不清晰时补拍；字幕和画面冲突时返回原视频核对。
  5. 阅读与分享。打开本地预览地址阅读 HTML；需要继续改写时编辑 book.md 并重跑渲染。公开发布需先确认内容使用权。

交互指南：把反馈说成可定位的修改，如“第 3 章 12:34 的界面图太糊，重截这一帧”“32:30 的定义域端点请按画面复核”。这比笼统要求“再完善一下”更容易准确修正。

阅读界面怎么用

  • 先看章节标题快速定位主题；代码块和表格用于复现与比较。
  • 点击图片放大查看界面或板书；点击卡片中的原视频链接核对上下文。
  • 如果嵌入播放器无法载入，优先使用“回到原视频”链接；本地预览应通过 http://localhost 打开，而不是直接双击 file:// 页面。

10 · 操作指南

操作者：命令流程与验收要点

以下命令需在仓库根目录执行。Windows 可将 python 替换为本机可用的 Python 3.12+ 解释器。AI 写书步骤由助手执行，脚本本身不会自动完成语义编排。

python -m pip install -r requirements.txt
python src/dump_transcript.py "<VIDEO_URL>"
# 平台确无字幕时：
python src/asr_transcript.py <VIDEO_ID> --sample-start 0 --sample-dur 180
python src/asr_transcript.py <VIDEO_ID> --restart
# 抽样合格后用 --restart 全量转写，再由 AI 助手生成 book.md
python src/capture_frames.py --setup-profile   # 首次登录时
python src/capture_frames.py <VIDEO_ID> "<VIDEO_URL>"
python src/post_process.py "<VIDEO_URL>" output/<VIDEO_ID>/book.md
python -m http.server 8080 --directory output/<VIDEO_ID>

浏览器访问 http://localhost:8080/book.html。若课程有官方主页，可先运行 course_assets.py <VIDEO_ID> --course-url <URL>，书稿完成后用 --audit 检查课件覆盖，再渲染 HTML。

交付前 5 项核对

  1. 字幕覆盖率与书稿的章节范围一致；ASR 专有名词已抽查。
  2. book.md 没有遗留的 SCREENSHOT: 占位；所有图片路径存在。
  3. 章节、表格、代码块和原视频回链能正常阅读；B 站分 P 跳转正确。
  4. 关键事实，尤其公式、端点、数字和软件界面名称，已对照画面或官方资料。
  5. 公开版本保留原作者署名、课程资料许可与必要的内容使用权说明。

现阶段验证与主要限制

已观察到的结果能够说明什么 / 不能说明什么
技术视频样例曾产出 10 个章节、17 张图，图片引用和网页渲染经本地检查；说明完整流程可执行，不等于所有视频都能无人审校交付。
高数 15 分钟人工试验人工核对 9 组候选，其中 6 组具体内容未进入原书；证明仅靠现有书稿选帧有遗漏风险，不代表全片公式总数。
独立视觉模型实验已知 9 组在候选中找到对应画面，审校版含 10 张图和 39 处公式节点；单个片段的已知组命中不能计算通用召回率。

需要持续控制的风险

  • 来源质量：平台无字幕、覆盖不足、ASR 错词或英文术语误识会影响后续重构。
  • 视觉遗漏：固定时间间隔抽帧可能错过短暂出现的公式；只从已写好的书稿选图也可能遗漏内容。
  • 模型误读：细小符号、区间端点、板书残留和未完成推导需要独立核对，不能用流畅文本掩盖疑点。
  • 运行环境：登录态、平台限制、代理、浏览器版本和视频可用性会影响字幕抓取及截帧。
  • 内容权利：开源代码不意味着自动取得视频、字幕和课件的再发布权。

改进方向：公式功能若要产品化，应补全可解码视频获取、时间覆盖报告、候选与待核对清单，再以跨视频人工标注集衡量漏检与误写。

13 · 结论与依据

总结、下一步与参考文献

VideoBook 已形成“字幕或 ASR → AI 结构化书稿 → 截图/官方资料 → HTML 阅读与可选发布”的本地工作流。AI 的核心贡献是把线性、口语化视频转成可阅读的知识结构；时间锚点、图片和原始材料使成果能够被复核。高数片段试验进一步说明，视觉信息必须参与数学内容整理。

建议的下一步

  1. 完成公式候选发现与视觉转写的跨视频验收，建立清晰的“已确认 / 待核对 / 未覆盖”状态。
  2. 统一 README 与实际 Python 版本要求，并把完整生成流程的人工审校点明确写入用户文档。
  3. 若面向外部用户，再验证部署、内容授权、批量处理成本与真实付费需求。
